# Evaluierung der Fehlerkorrektur und authentifizierten Verschlüsselung des MAGIC-Modus auf einem Mikrocontroller mit externem Speicher

## Allgemeines
Mit dieser Arbeit handelt es sich um meine Bachelorarbeit an der Hochschule RheinMain. Dazu wurde eine Implementierung des MAGIC-Modus erstellt und mit dem Hamming-Code bezüglich der Fehlerkorrektur verglichen. Dazu wurden die Takte auf einem Mikrocontroller mit externen SRAM gemessen. Dabei handelt es sich um das ChipSHOUTER® CW521 Ballistic Gel Board. Die Messergebnisse befinden sich im Ordner ``evaluation``. Die [PDF-Datei](./Bachelorarbeit_AI_Jonas_Gilbert_1288740.pdf) dieser Arbeit befindet sich im Hauptordner von diesem Projekt. Darin werden unter anderem die jeweiligen Programmteile genauer erläutert.

## Abstract
### Deutsch
In dieser Bachelorarbeit soll der MAGIC-Modus auf einem Mikrocontroller evaluiert werden. Dieser Modus stellt gleichzeitig eine authentifizierte Verschlüsselung und Fehlerkorrektur zur Verfügung. MAGIC wurde implementiert und mit dem Hamming-Code bezüglich der Fehlerkorrektur verglichen. Für die Evaluierung wurden die Taktzyklen und der Speicherverbrauch auf dem Mikrocontroller betrachtet. Die Evaluierungsergebnisse zeigen, dass der Hamming-Code in Bezug auf die Fehlerkorrektur deutlich schneller ist. Vor allem da ein beliebiger Hashwert im Vergleich zu MAGIC verwendet werden kann. Es werden jedoch mindestens 128 Bits zusätzlicher Speicher in Verglich zum MAGIC-Modus benötigt. Jedoch kann MAGIC in der Theorie mehr Fehler erkennen und korrigieren als der Hamming-Code. Dies zeigt, dass man nach aktuellem Stand weiterhin den Hamming-Code verwenden sollte. Jedoch zeigt die Arbeit auch, dass durch MAGIC durchaus die Komplexität verringert wird. Sollte man schneller einen Hashwert beim MAGIC-Modus finden, kann es in der Praxis problemlos eingesetzt werden.

### English
In this bachelor thesis, the MAGIC mode should be evaluated on a microcontroller. This mode supports authenticated encryption and error correction simultaneously. MAGIC was implemented and compared with the Hamming code regarding the error correction. For the evaluation on the microcontroller, the clock cycles and the memory usage were viewed. The evaluation results prove that the Hamming code is much faster in terms of error correction because an arbitrary hashkey can be used to generate a MAC. For this, MAGIC cannot use an arbitrary hashkey. But at least 128 bits more are required compared to the MAGIC mode. In theory, MAGIC can detect and correct more errors than Hamming code. The results indicate that the Hamming code should still be used according to the current status. This thesis shows as well that the complexity with MAGIC is reduced. When it is possible to find a hashkey more efficient in the MAGIC mode, you can use it without problems in the real world.


## Programm und Tests ausführen
Es gbit zwei Makefiles in diesem Projekt. Ein [Makefile](./microcontroller/cw521/makefile) ist für die Kompilierung für den Mikrocontroller zuständig. Wie man die Datei und Tests auf dem Mikrocontroller ausführt, kann man in der [PDF-Datei](./Bachelorarbeit_AI_Jonas_Gilbert_1288740.pdf) nachlesen.

Das andere [Makefile](./microcontroller/cw521/magic_bachelorarbeit/Makefile) sorgt für eine lokale Kompilierung. Bei der lokalen Kompilierung wird eine ausführbare Datei im Ordner ``./microcontroller/cw521/magic_bachelorarbeit/bin`` erstellt, die man dann ausführen kann. Dieses Makefile erstellt erstellt außerdem in diesem Ordner mit dem Kommando ``make test`` eine ausführbare Datei für die lokale Ausführung der Tests.
